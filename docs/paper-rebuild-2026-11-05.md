# 阅读页错乱的真正原因（2026-11-05 第二轮）

> 上一轮报告（`paper-audit-2026-11-05.md`）把病灶归到「图注吞正文」「参考文献不足」。
> 这一轮逐篇对着 PDF 看，发现还要往上一层：**绝大多数"图"根本不是图。**

## 一、根因：页眉被切成了几百张位图

以 257 号为例，PDF 里 287 张位图，其中 **286 张是 2×2 像素的噪点**，
剩下 1 张是 323×303 的刊头封面。也就是说：**这篇论文一张插图都没有**。

但库里的 Markdown 有 **40 个 `图 N`**，每张图下面还挂着
`附图 M（原文插图）UBBISH`、`附图 M（原文插图）Volume` 这类图注。

12 篇抽样统计（326 个"图"）：

| 类型 | 数量 | 来历 |
|---|---|---|
| 页眉切片（高 30–60 px） | 273 | `RUBBISH \| Volume XX \| March 2026` 被逐词切图 |
| 噪点（2×2 px） | 15 | PDF 抗锯齿碎屑 |
| 刊头 logo（687×264，页页重复） | 6 | 期刊横幅 |
| **真插图** | **32** | 论文真正的图 |

早期管线把每一张位图都编了号、配了题，题还粘上了相邻正文，于是有了
"图 1：附图 3（原文插图）UBBISH" 这种行。手机上看到的重叠、错位、
满屏图注，全是这么来的——**不是渲染器的问题，是源文件里凭空多出 294 个图**。

## 二、修法：重写提取器 `scripts/paper/rebuild.py`

老 `extract.py` 按 block 拼文字，把数字（独立绘制单元）和页眉切图都当正文，
所以越修越乱。新工具换了读法：

1. **按栏裁剪取文**：先用行的 x 分布算栏间距，再「整宽行切带、带内先左栏
   后右栏」，逐块 `get_text(clip=…, sort=True)`——数字和上下标不再丢
   （`6.8 s`、`41 s`、`1.00047` 全部回来了）。
2. **页眉页脚按跨页重复剔除**：同一串短文本出现在 ≥2 页就是页眉。
3. **图片只留真图**：高度 < 80pt 的位图、首页上方的刊名 logo、同 xref 重复
   出现的一律丢弃；真图按纵向位置插回所在栏。
4. **逐行重排段落**：标题自成一节、正文按句末标点收口、跨栏不粘连。

```
python -m scripts.paper rebuild a.pdf -o a.md --images img/
python -m scripts.paper inline  a.md --img-dir img/     # 图片压成 data URI
python -m scripts.paper lint    a.md                     # 改到 error 0
python -m scripts.paper docx    a.md -o a.docx --title "…"
```

## 四、还剩什么

库内 267 篇，本轮处理 12 篇。剩余 255 篇里仍有大量"假图"——按 12 篇抽样
比例推算，全库 3000+ 个 `图 N` 里大概只有一成是真图。建议按同样流程批量处理：

```
# 1. 全库先跑 rebuild，输出到 /tmp/rebuild/<id>/，与原稿比 lint 分数
# 2. 新稿分数 ≥ 原稿才替换（自动闸门），否则保留原稿
# 3. 替换后逐篇派编辑补摘要/章节/文献/图注（本轮 12 篇的流程）
```

自动闸门这一步很关键：rebuild 对扫描版或版式奇特的 PDF 不一定更好，
只认分数、不认"看起来更整齐"。
