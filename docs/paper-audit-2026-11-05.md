> 对象：库内 267 篇已刊稿的 Markdown 源文件

## 一、结论先说

**阅读页没有坏，源文件是坏的。**

渲染器只有一套（`manuscript-view.tsx` → markdown-it），同一套代码在同一台手机上
把 105 号渲染得很正常，把 257 号渲染得乱七八糟。差别不在前端，在这两篇的
Markdown 长得不一样。这批 Markdown 是早期用 `pymupdf4llm` 从 PDF 批量转出来的，
双栏排版一旦判断错，就会产生下面这些结构性错误。

## 四、典型病灶

### 4.1 章节乱序（E005）
289 号：

```
1 Introduction → 2 Methodology → 4 Conclusion → 3 Results and Discussion
```

这是双栏 PDF 按坐标排序的直接后果：右栏下半部分（结论）在纵坐标上高于
左栏下半部分（结果）。已由 `fix.py` 按编号重排。

### 4.2 图注吞正文（E006）
105 号：

```
图 2：鸟运定律总结图示表 1 ：鸟运定律总结
```

一张图题里塞进了下一张表的表题。257 号更严重，图注里塞的是整段正文。
已按"结构标记"（`###`、下一个图号、第一个句号）断开，剩余 313 处需要
编辑对着原图重写图题。

### 4.3 数字被吃掉
203 号的作者名在库里是 `Claude Opus 4.` 与 `Deepseek-V`，原稿 PDF 里是
`4.71` 与 `V32`。数学字体里的数字在提取时整段丢失，句子依然通顺，只是
事实没了。新的 `extract.py` 能从同一份 PDF 正确读出 `4.71`，重跑提取即可修好。

### 4.4 内嵌 base64 图片
52 篇单篇超过 300 KB（289 号 287 KB、105 号 281 KB）。手机上首屏要等这些
字符串下载完才能渲染。新的提取器把图片落成文件，不再塞 base64。

## 五、处理方式（已执行）

1. **自动修复**：`scripts/paper fix` 只做确定性的事——标点前空格、相邻重复段、
   重复子句、章节按编号重排、图注断句。129 篇，全部带 `.bak-fix` 备份，
   可 `python -m scripts.paper restore /data/uploads` 一键回滚。
2. **不动**：摘要扩写、补章节、补文献、改文献格式——这些需要判断，脚本不碰。
3. **导出改造**：`/api/catalog/{id}/export?format=docx` 改用官方模板，
   下载到的 Word 就是可以直接改的工作稿（203 号 4.1 MB → 46 KB）。

## 六、剩下的怎么办

剩下的 313 + 244 + 186 + 142 + 135 条硬伤不可能靠脚本消掉，只能逐篇编辑。
建议按分数从低到高处理，每篇的操作是：

```
python -m scripts.paper docx <原稿>.md -o <编号>.docx --title "…" --authors "…"
# 在 Word 里按 docs/paper-specification.md 第 1 节逐项核对、补写
# 改完回传，入库时再跑一次 lint，error 清零才允许发布
```

`audit-2026-11-05.json` 里有每一篇的检查码明细，可以直接当工单用。
