# RUBBISH 论文规范（可执行版）

> 版本 2.0 · 2026-11-05
> 上位文件：`docs/editorial-standards.md`（编辑立场与评审流程）。本文只管**一篇稿子长什么样**，
> 每一条都能被 `scripts/paper` 里的程序检查出来，检查码写在条目后面。
> 冲突时以 editorial-standards.md 为准；本文只补充它没有落到字面上的部分。

## 0. 为什么要有这份文件

站上 267 篇存稿，用程序体检了一遍，平均 56.7 分。问题不是"写得不好"，是**形状不对**：

| 症状 | 命中篇次 |
|---|---|
| 图注把下一段正文吞进同一行 | 462 |
| 参考文献不足 8 条 | 244 |
| 缺必备章节（引言/方法/结果/讨论/结论） | 187 |
| 参考文献缺 `[J]/[M]` 类型标识 | 142 |
| 摘要不在 200–350 字 | 136 |
| 章节编号乱序（4 结论排在 3 结果前面） | 24 |
| 相邻段落完全重复 | 3 |

这些在手机阅读页上全部看得见。所以规范不能只写在纸上——**每条都要有检查码，
每次入库都要跑一遍**。

## 1. 结构总表

一篇文章由下列模块按序组成。`必须` 一列：研究论文为 M，综述/随笔为 O（可省）。

| # | 模块 | 必须 | 字数（汉字） | 内容要求 | 检查码 |
|---|---|---|---|---|---|
| 1 | 题名 | M | 8–30 | 名词短语，不用"的研究""初探"凑字；可加副题名（破折号） | — |
| 2 | 作者 | M | — | 真实姓名，按贡献排序；通讯作者标 `*` | — |
| 3 | 单位 | M | — | 一级单位 + 二级单位 + 城市 + 邮编 | — |
| 4 | 摘要 | M | **200–350** | 问题 / 方法 / 结果 / 结论 四要素齐全 | E001 E002 |
| 5 | 关键词 | M | **3–8 个** | 分号分隔，名词，不用整句 | E003 |
| 6 | 引言 | M | 500–1200 | 现象 → 研究缺口 → 本文做什么 → 贡献清单 | E004 |
| 7 | 相关工作 | O | 800–2000 | 按立场分组，不逐篇罗列 | E004 |
| 8 | 方法 | M | 1000–3000 | 数据、样本、变量、模型/论证框架可复现 | E004 |
| 9 | 结果 | M | 1000–3000 | 总—分，每节对应 1 个图表 | E004 |
| 10 | 讨论 | M | 600–2000 | 含义 → 局限 → 启示 | E004 |
| 11 | 结论 | M | 200–500 | 重申发现，不引入新证据 | E004 |
| 12 | 致谢 | O | ≤150 | 基金号、审稿人；AI 使用在此声明 | — |
| 13 | 参考文献 | M | **≥ 8 条** | GB/T 7714-2015 顺序编码制 | E012 E013 E014 |
| 14 | 三段声明 | M | — | 数据可用性 / 作者贡献 / 利益冲突 | — |

正文总量：短篇 2500–5000，中篇 5000–8000，长篇 8000+（见 editorial-standards §2）。

## 2. 模块细则

### 2.1 题名
- 不加书名号，不用句号；副题名用破折号 `——`，不用冒号。
- 避免"研究""探析""浅谈"等无信息词（荒诞赛道可以反着来，但要有意为之）。

### 2.2 摘要（E001 / E002）
四句话能覆盖就够，但四要素缺一不可：
1. **问题**：研究什么现象，为什么值得研究；
2. **方法**：数据从哪来、样本多大、怎么分析；
3. **结果**：给出**具体数字**，不要"效果显著"；
4. **结论**：意味着什么，适用范围到哪。

禁止："本文具有重要意义""填补了空白""具有理论与实践价值"。
摘要是**连续段**，可以分 2–3 段，但合计 200–350 字。

### 2.3 关键词（E003）
3–8 个，分号 `；` 分隔，从大到小排列（学科 → 主题 → 方法）。

### 2.4 引言
四步走，缺一步读者就跟不上：
1. 现象（可引数据）；
2. 已有研究做到哪；
3. 缺口是什么（本文的立足点）；
4. 本文做什么、贡献几条（编号列出）。

### 2.5 方法
可复现是唯一标准。至少给出：数据来源与时间窗、样本量与筛选规则、
变量定义与测量方式、分析模型与软件版本。模拟数据必须写明"本文数值来自模拟"
并给参数表。

### 2.6 结果
按"总—分"写：先一句话给主结论，再逐条展开。**每一个图表都必须在正文里被
引用**（W004），否则读者不知道它为什么在那儿。

### 2.7 讨论
三段：含义（和已有研究对上了吗）→ 局限（样本、方法、外推）→ 启示（实践/政策）。

### 2.8 结论
只重申，不新增证据、不新增引用。200–500 字。

## 3. 图表规范

### 3.1 图
| 项 | 要求 | 检查码 |
|---|---|---|
| 编号 | 图 1、图 2…连续，不跳号 | E007 |
| 图题位置 | **图下方**，居中，"图 1　题名"（全角空格） | — |
| 图题长度 | ≤ 40 字，**不含正文** | E006 |
| 正文引用 | 必须出现"见图 1" | W004 |
| 分辨率 | ≥ 300 dpi，位图宽 ≥ 1000 px | — |
| 宽高比 | 不要做超宽条图（宽高比 > 5 的图在手机上缩到不可读） | — |
| 数据来源 | 图题末句写"数据来源：…"；模拟数据写"模拟" | — |
| 可访问性 | 颜色不作唯一编码，配线型/标记 | — |
| 无图注 | 每张图都要有图题 | W008 |

### 3.2 表
| 项 | 要求 | 检查码 |
|---|---|---|
| 编号 | 表 1、表 2…连续 | E007 |
| 表题位置 | **表上方**，居中 | — |
| 线型 | **三线表**：顶线、表头线、底线；**不画竖线** | — |
| 单位 | 写在表头内："耗时（ms）"，不在单元格里重复 | — |
| 显著性 | `*`/`**` 在表注中说明对应 p 值 | — |

### 3.3 图注被正文污染（E006，命中 462 处，最严重）
PDF 双栏提取时，图注经常把下一栏的开头整段吞进来：

```
图 3：附图 2（原文插图）与摘要不同并形成矛盾的是，本文在此继续进行，这导致混乱
```

判据：图注正文 > 40 字，或含 2 个以上句号，或里面又出现"图 N / 表 N"。
处理：在结构标记（`###`、下一个图号、第一个句号）处断开，后半段还原为正文。
`scripts/paper fix` 能自动处理其中一部分，剩下的必须人工看图补题。

## 4. 公式、量与单位

- 公式独立成行，右侧编号 `(1)(2)`；正文引用写"式(1)"。
- 不用图片代替公式；不用裸露 LaTeX（`\frac`、`$$`）——阅读页会原样显示（E011）。
- 量符号斜体，单位正体，量与单位间空一格：`t = 12 s`。
- 单位用法定计量单位（GB 3100–3102），不用"斤""亩""度"。
- 百分数写 `28.7%`，区间写 `20%–30%`，不用 `20-30%`。

## 5. 语言与标点（GB/T 15834-2011）

| 规则 | 反例 | 正例 |
|---|---|---|
| 中文标点前不留空格 | `不堪入目 、目不忍睹` | `不堪入目、目不忍睹` |
| 中文之间不加空格 | `本 文 提 出` | `本文提出` |
| 中英文之间加半角空格 | `基于Transformer模型` | `基于 Transformer 模型` |
| 省略号用 `……` | `。。。` | `……` |
| 破折号用 `——` | `--` / `— —` | `——` |
| 引号用弯引号 | `"文本"` | `“文本”` |
| 数字与单位 | `12s` | `12 s` |

自动检查：W002（标点前空格）。其余由 `normalize.py` 在入库时统一处理。

## 6. 参考文献（GB/T 7714-2015 顺序编码制）

### 6.1 格式模板

```
[序号] 主要责任者. 题名: 其他题名信息[文献类型标识/文献载体标识]. 出版地: 出版者, 出版年: 页码.
```

| 类型 | 标识 | 示例 |
|---|---|---|
| 期刊 | `[J]` | `[1] 张三, 李四. 标题[J]. 刊名, 2025, 12(3): 45-58. DOI:10.xxxx/yyyy.` |
| 专著 | `[M]` | `[2] 王五. 书名[M]. 北京: 科学出版社, 2024: 12-30.` |
| 论文集析出 | `[M]//` | `[3] 赵六. 篇名[M]//论文集名. 上海: 复旦大学出版社, 2023: 5-9.` |
| 会议 | `[C]` | `[4] 孙七. 篇名[C]//会议名. 城市: 出版者, 2025: 1-8.` |
| 学位论文 | `[D]` | `[5] 周八. 题目[D]. 北京: 北京大学, 2024.` |
| 标准 | `[S]` | `[6] GB/T 7714—2015 信息与文献 参考文献著录规则[S]. 北京: 中国标准出版社, 2015.` |
| 报告 | `[R]` | `[7] 机构. 报告名[R]. 城市: 机构, 2025.` |
| 电子资源 | `[EB/OL]` | `[8] 作者. 题名[EB/OL]. (2025-01-01)[2025-06-01]. https://….` |

### 6.2 硬性要求

- **≥ 8 条**（E012）；
- 每条必须有类型标识（E013）；
- 有 DOI 的必须给 DOI（E014）；
- 正文按出现顺序标 `[1][2]`，文末同序；
- 作者 ≤ 3 人全列，> 3 人列前 3 加"等"；
- 自引 ≤ 20%。

## 7. 文件与排版

### 7.1 提交格式
| 格式 | 用途 | 要求 |
|---|---|---|
| `.docx` | **主格式** | 用官方模板（`scripts/paper docx`），图表为可编辑对象 |
| `.md` | 在线阅读 | 站内渲染最好 |
| `.pdf` | 存档 | 必须附源文件；不接受扫描件 |

### 7.2 Word 模板参数（代码实现见 `app/modules/submission/docx_template.py`）

| 部位 | 字体 | 字号 | 段落 |
|---|---|---|---|
| 篇名 | 黑体 | 小二 18pt | 居中，段后 0.5 行 |
| 作者 | 楷体 | 小四 12pt | 居中 |
| 单位 | 宋体 | 小五 9pt | 居中 |
| 摘要/关键词 | 宋体（标签黑体） | 五号 10.5pt | 两端对齐，首行不缩进 |
| 一级标题 | 黑体 | 四号 14pt | 段前 0.5 行 |
| 二级标题 | 黑体 | 五号加粗 | 段前 0.3 行 |
| 正文 | 宋体 | 五号 10.5pt | 首行缩进 2 字符，1.5 倍行距 |
| 图题/表题/表内 | 宋体 | 小五 9pt | 图下、表上，居中 |
| 参考文献 | 宋体 | 小五 9pt | 悬挂缩进 2 字符 |

页面：A4，上下 2.8 cm，左右 3.0 cm，页码居中页脚，页眉"RUBBISH + 篇名"。

## 8. 流水线：PDF → Word → 编辑 → 入库

这是本规范落地的方式。**不要直接拿 PDF 提取结果上线**——阅读页的错乱全是从这一步进来的。

```
① 提取   scripts/paper extract a.pdf -o a.json --images img/ --md a.md
         · 分栏判定（整宽块作分隔带，带内先左栏后右栏）
         · 角色判定（字号→标题层级，图 N/表 N→图注，其余→正文）
         · 图片落地成文件（不再塞 base64）
              ↓
② 成稿   scripts/paper docx a.md -o a.docx --title "…" --authors "…"
         · 套官方模板：标题/作者/单位/摘要/关键词/正文/图表/参考文献
         · 缺图注的图自动编号占位，等编辑补
              ↓
③ 编辑   在 Word 里按本规范逐项核对（第 1 节结构表）
         · 该补的补（摘要四要素、缺失章节、文献）
         · 该改的改（图注、图表编号、标点、格式）
         · 图片可以直接换：网上下载无水印图，按图题位置插入
              ↓
④ 入库   上传 .docx（mammoth → Markdown → normalize → lint）
         · lint 不通过（有 error）不允许直接发布，只能存草稿
```

### 8.1 每步对应命令

```bash
# ① 提取
python -m scripts.paper extract paper.pdf -o out/paper.json --images out/img --md out/paper.md

# ② 生成官方模板 Word
python -m scripts.paper docx out/paper.md -o out/paper.docx \
    --title "篇名" --authors "张三、李四" --affiliations "某某大学;某研究所"

# ③ 体检（改完再跑，直到没有 error）
python -m scripts.paper lint out/paper.md

# ④ 批量体检 / 批量修可机械判定的问题
python -m scripts.paper audit /data/uploads --out audit.json
python -m scripts.paper audit /data/uploads --apply     # 带 .bak-fix 备份
python -m scripts.paper restore /data/uploads           # 回滚
```

## 10. 与旧版的关系

- `docs/editorial-standards.md` v1.1 继续管**立场**（选题、伦理、评审、AI 声明）；
- 本文件管**形状**（结构、字数、格式、图表、文献）；
- 两者的检查项在 `scripts/paper/lint.py` 里合并执行，检查码即本文第 9 节。
